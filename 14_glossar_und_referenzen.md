## GitHub-Glossar

Dieses Glossar enthält wichtige Begriffe und Konzepte, die im Zusammenhang mit GitHub und Git verwendet werden. Es dient als Nachschlagewerk für Anfänger und erfahrene Benutzer gleichermaßen.

### A

**Actions**  
Eine CI/CD-Plattform (Continuous Integration/Continuous Deployment) von GitHub, die es ermöglicht, automatisierte Workflows direkt in GitHub-Repositories zu definieren und auszuführen.

**API (Application Programming Interface)**  
Eine Schnittstelle, die es Entwicklern ermöglicht, programmatisch mit GitHub zu interagieren. GitHub bietet sowohl eine REST API als auch eine GraphQL API.

**Arctic Code Vault**  
Ein Archiv im arktischen Permafrost auf Spitzbergen, Norwegen, das im Rahmen des GitHub Archive Program eingerichtet wurde, um Open-Source-Code für mindestens 1.000 Jahre zu bewahren.

**Assignee**  
Eine Person, der ein Issue oder Pull Request zugewiesen wurde und die für dessen Bearbeitung verantwortlich ist.

**Authentication**  
Der Prozess der Identitätsüberprüfung bei der Anmeldung bei GitHub, der verschiedene Methoden wie Passwörter, persönliche Zugriffstoken oder SSH-Schlüssel umfassen kann.

### B

**Badge**  
Ein visuelles Kennzeichen, das in README-Dateien oder Profilen angezeigt wird, um Status, Erfolge oder andere Informationen darzustellen.

**Base Branch**  
Der Zielbranch, in den Änderungen aus einem Pull Request zusammengeführt werden sollen.

**Blame**  
Eine GitHub-Funktion, die anzeigt, wer welche Zeilen in einer Datei wann geändert hat, was bei der Nachverfolgung von Änderungen und der Identifizierung von Verantwortlichen hilfreich ist.

**Branch**  
Eine parallele Version eines Repositories, die es ermöglicht, an verschiedenen Funktionen oder Fehlerbehebungen zu arbeiten, ohne den Hauptcode zu beeinträchtigen.

**Branch Protection Rules**  
Einstellungen, die festlegen, wer Änderungen an bestimmten Branches vornehmen kann und welche Bedingungen erfüllt sein müssen, bevor Änderungen zusammengeführt werden können.

### C

**Cherry-pick**  
Ein Git-Befehl, der es ermöglicht, einen bestimmten Commit aus einem Branch zu nehmen und auf einen anderen Branch anzuwenden.

**CI/CD (Continuous Integration/Continuous Deployment)**  
Praktiken in der Softwareentwicklung, bei denen Code regelmäßig integriert, getestet und bereitgestellt wird. GitHub Actions ist ein Werkzeug für CI/CD.

**Clone**  
Der Prozess des Erstellens einer lokalen Kopie eines Remote-Repositories auf dem eigenen Computer.

**Code Owners**  
Personen oder Teams, die in einer CODEOWNERS-Datei als verantwortlich für bestimmte Teile des Codes definiert sind und deren Genehmigung für Änderungen an diesen Teilen erforderlich sein kann.

**Code Scanning**  
Eine GitHub-Funktion, die automatisch Sicherheitslücken und Fehler im Code identifiziert.

**Codespace**  
Eine cloudbasierte Entwicklungsumgebung, die direkt in GitHub integriert ist und es ermöglicht, Code zu schreiben, zu testen und zu debuggen, ohne lokale Einrichtung.

**Commit**  
Eine Änderung oder eine Reihe von Änderungen an Dateien in einem Repository, die mit einer eindeutigen ID und einer Nachricht versehen ist.

**Commit Hash**  
Eine eindeutige Kennung (SHA-1-Hash) für einen Commit, die zur Identifizierung und Referenzierung des Commits verwendet wird.

**Contributor**  
Eine Person, die Code, Dokumentation oder andere Inhalte zu einem Repository beigetragen hat.

### D

**Dependabot**  
Ein GitHub-Tool, das automatisch Sicherheitslücken in Abhängigkeiten erkennt und Pull Requests erstellt, um diese zu beheben.

**Dependency Graph**  
Eine Visualisierung der Abhängigkeiten eines Projekts, die zeigt, welche Pakete und Bibliotheken verwendet werden.

**Deployment**  
Der Prozess der Bereitstellung von Code in einer Produktions- oder Testumgebung.

**Diff**  
Eine Darstellung der Unterschiede zwischen zwei Versionen einer Datei oder zwischen zwei Commits.

**Discussion**  
Ein GitHub-Feature, das Raum für Fragen, Ankündigungen und offene Gespräche bietet, die nicht direkt mit Issues oder Pull Requests verbunden sind.

### E

**Environment**  
Eine Konfiguration für Deployments in GitHub, die Schutzregeln und Secrets enthalten kann.

**Event**  
Eine Aktion, die in einem GitHub-Repository stattfindet, wie das Erstellen eines Issues, das Öffnen eines Pull Requests oder das Pushen von Commits.

### F

**Fork**  
Eine persönliche Kopie eines Repositories, die es ermöglicht, Änderungen vorzunehmen, ohne das Original-Repository zu beeinflussen.

**Force Push**  
Ein Git-Befehl, der lokale Änderungen auf ein Remote-Repository überträgt und dabei die Remote-Historie überschreibt, was potenziell gefährlich sein kann.

**FUNDING.yml**  
Eine Datei, die in einem Repository platziert werden kann, um Finanzierungsoptionen für das Projekt anzugeben.

### G

**Gist**  
Ein einfacher Weg, Code-Snippets und Notizen zu teilen, ohne ein vollständiges Repository zu erstellen.

**Git**  
Ein verteiltes Versionskontrollsystem, das die Grundlage für GitHub bildet.

**Git LFS (Large File Storage)**  
Eine Git-Erweiterung, die große Dateien effizient verwaltet, indem sie Referenzen statt der tatsächlichen Dateien im Repository speichert.

**GitHub Apps**  
Integrationen, die spezifische Aktionen in Repositories oder Organisationen ausführen können und feinkörnige Berechtigungen haben.

**GitHub CLI**  
Ein Kommandozeilenwerkzeug, das es ermöglicht, GitHub-Funktionen direkt von der Kommandozeile aus zu nutzen.

**GitHub Copilot**  
Ein KI-gestützter Programmierassistent, der Codevorschläge basierend auf Kommentaren und Kontext macht.

**GitHub Desktop**  
Eine benutzerfreundliche Anwendung, die Git- und GitHub-Funktionen mit einer grafischen Benutzeroberfläche bereitstellt.

**GitHub Enterprise**  
Eine Version von GitHub für Unternehmen, die entweder in der Cloud (GitHub Enterprise Cloud) oder selbst gehostet (GitHub Enterprise Server) betrieben werden kann.

**GitHub Flow**  
Ein einfacher, branchbasierter Workflow für die Zusammenarbeit an GitHub-Projekten.

**GitHub Mobile**  
Eine mobile Anwendung, die es ermöglicht, GitHub-Funktionen auf iOS- und Android-Geräten zu nutzen.

**GitHub Pages**  
Ein Hosting-Service für statische Websites direkt aus GitHub-Repositories.

**GitHub Sponsors**  
Ein Programm, das es Entwicklern ermöglicht, finanzielle Unterstützung für ihre Open-Source-Arbeit zu erhalten.

**Gitignore**  
Eine Datei, die Git mitteilt, welche Dateien oder Verzeichnisse bei der Versionskontrolle ignoriert werden sollen.

**GraphQL API**  
Eine API-Abfragesprache, die es ermöglicht, genau die Daten anzufordern, die benötigt werden, und mehrere Ressourcen in einer einzigen Anfrage zu kombinieren.

### H

**Head Branch**  
Der Branch, der die Änderungen enthält, die in einen Pull Request eingebracht werden sollen.

**Hook**  
Ein Mechanismus, der es ermöglicht, auf bestimmte Ereignisse in einem Repository zu reagieren, wie Webhooks oder Git-Hooks.

### I

**Issue**  
Ein Eintrag in einem GitHub-Repository, der verwendet wird, um Fehler, Verbesserungsvorschläge oder Aufgaben zu verfolgen.

**Issue Template**  
Eine vordefinierte Struktur für neue Issues, die hilft, konsistente und vollständige Informationen zu sammeln.

### J

**Jekyll**  
Ein Generator für statische Websites, der eng in GitHub Pages integriert ist und es ermöglicht, Websites aus Markdown-Dateien zu erstellen.

### K

**Kubernetes**  
Eine Open-Source-Plattform zur Automatisierung der Bereitstellung, Skalierung und Verwaltung von containerisierten Anwendungen, die oft mit GitHub Actions für CI/CD verwendet wird.

### L

**Label**  
Ein Tag, das Issues und Pull Requests zugewiesen werden kann, um sie zu kategorisieren und zu filtern.

**License**  
Eine Datei, die die rechtlichen Bedingungen festlegt, unter denen der Code eines Repositories verwendet werden kann.

**Lint**  
Der Prozess der statischen Codeanalyse, um potenzielle Fehler, stilistische Probleme und verdächtige Konstrukte zu identifizieren.

### M

**Main Branch**  
Der Hauptentwicklungszweig eines Repositories, früher oft als "master" bezeichnet.

**Maintainer**  
Eine Person, die für die Verwaltung und Pflege eines Repositories verantwortlich ist.

**Markdown**  
Eine leichtgewichtige Auszeichnungssprache, die in GitHub für README-Dateien, Issues, Pull Requests und andere Dokumentation verwendet wird.

**Merge**  
Der Prozess des Zusammenführens von Änderungen aus einem Branch in einen anderen.

**Merge Conflict**  
Eine Situation, die auftritt, wenn Git nicht automatisch Änderungen aus verschiedenen Branches zusammenführen kann, weil sie sich überschneiden.

**Milestone**  
Ein Ziel oder eine Etappe in einem Projekt, dem Issues und Pull Requests zugeordnet werden können.

### N

**Notification**  
Eine Benachrichtigung über Aktivitäten in Repositories, an denen man beteiligt ist, wie neue Issues, Kommentare oder Pull Requests.

### O

**OAuth App**  
Eine Anwendung, die die OAuth-Authentifizierung verwendet, um im Namen eines Benutzers auf GitHub-Ressourcen zuzugreifen.

**Organization**  
Ein gemeinsames Konto auf GitHub, das mehrere Repositories und Benutzer verwalten kann und erweiterte Funktionen für Teams bietet.

### P

**Package**  
Eine Software oder Bibliothek, die über die GitHub Packages-Registrierung veröffentlicht und verteilt werden kann.

**Pages**  
Siehe GitHub Pages.

**Personal Access Token (PAT)**  
Ein Token, das anstelle eines Passworts für die Authentifizierung bei GitHub verwendet werden kann, mit spezifischen Berechtigungen.

**PR (Pull Request)**  
Ein Vorschlag, Änderungen aus einem Branch in einen anderen zu übernehmen, der Diskussion, Review und Zusammenführung ermöglicht.

**Project**  
Ein Projektmanagement-Tool in GitHub, das es ermöglicht, Issues, Pull Requests und Notizen in anpassbaren Ansichten zu organisieren.

**Protected Branch**  
Ein Branch mit speziellen Regeln, die festlegen, wer pushen, zusammenführen oder löschen kann, oft verwendet für wichtige Branches wie "main".

**Pull**  
Der Prozess des Abrufens und Integrierens von Änderungen aus einem Remote-Repository in das lokale Repository.

**Push**  
Der Prozess des Sendens lokaler Änderungen an ein Remote-Repository.

### Q

**Query**  
Eine Anfrage an die GitHub-API oder -Suche, um spezifische Informationen zu erhalten.

### R

**Rate Limit**  
Eine Begrenzung der Anzahl von Anfragen, die an die GitHub-API in einem bestimmten Zeitraum gestellt werden können.

**README**  
Eine Datei, die Informationen über ein Repository enthält, wie Beschreibung, Installation, Verwendung und Beitragsrichtlinien.

**Rebase**  
Ein Git-Befehl, der die Commit-Historie neu anordnet, indem er Commits auf eine neue Basis anwendet.

**Release**  
Eine benannte Sammlung von Software, Dokumentation und anderen Ressourcen, die einen bestimmten Zustand eines Repositories darstellt.

**Remote**  
Ein gemeinsames Repository, das auf einem Server gehostet wird und mit dem lokale Repositories synchronisiert werden können.

**Repository (Repo)**  
Ein Speicherort für ein Projekt, der alle Dateien, die Versionshistorie und Metadaten enthält.

**REST API**  
Eine API, die auf dem REST-Architekturstil basiert und es ermöglicht, mit GitHub-Ressourcen über HTTP-Anfragen zu interagieren.

**Review**  
Der Prozess der Überprüfung von Änderungen in einem Pull Request, bei dem Kommentare, Vorschläge und Genehmigungen abgegeben werden können.

### S

**Secret**  
Eine vertrauliche Information, wie ein Passwort oder API-Schlüssel, die sicher in GitHub gespeichert und in Workflows verwendet werden kann.

**Secret Scanning**  
Eine GitHub-Funktion, die Repositories auf versehentlich commitete Secrets wie API-Schlüssel oder Zugangsdaten überprüft.

**Security Advisory**  
Eine Mitteilung über eine Sicherheitslücke in einem Projekt, die Details, Auswirkungen und Behebungsinformationen enthält.

**Self-hosted Runner**  
Ein Server, der GitHub Actions-Workflows außerhalb der von GitHub bereitgestellten Infrastruktur ausführt.

**SSH Key**  
Ein kryptografischer Schlüssel, der für die sichere Authentifizierung bei GitHub über das SSH-Protokoll verwendet wird.

**Squash**  
Das Zusammenfassen mehrerer Commits in einen einzigen Commit, oft verwendet beim Zusammenführen von Pull Requests.

**Stale**  
Ein Issue oder Pull Request, der für einen längeren Zeitraum keine Aktivität aufweist.

**Star**  
Eine Funktion, mit der Benutzer ihr Interesse an einem Repository zeigen können, ähnlich einem Lesezeichen oder "Gefällt mir".

**Status Check**  
Eine Überprüfung, die auf einen Pull Request angewendet wird, um sicherzustellen, dass bestimmte Bedingungen erfüllt sind, bevor er zusammengeführt werden kann.

**Submodule**  
Ein Git-Repository innerhalb eines anderen Git-Repositories, das es ermöglicht, externe Abhängigkeiten zu verwalten.

### T

**Tag**  
Eine Markierung, die auf einen bestimmten Commit in der Git-Historie verweist, oft verwendet, um Releases zu kennzeichnen.

**Team**  
Eine Gruppe von Organisationsmitgliedern mit definierten Rollen und Berechtigungen.

**Template Repository**  
Ein Repository, das als Vorlage für neue Repositories dienen kann, komplett mit Dateien, Verzeichnissen und Konfigurationen.

**Token**  
Siehe Personal Access Token.

**Two-Factor Authentication (2FA)**  
Eine Sicherheitsfunktion, die neben dem Passwort eine zweite Verifizierungsmethode erfordert, um sich bei GitHub anzumelden.

### U

**Upstream**  
Das Original-Repository, von dem ein Fork erstellt wurde.

**User**  
Ein Konto auf GitHub, das Repositories erstellen, an Projekten teilnehmen und mit anderen Benutzern interagieren kann.

### V

**Vulnerability**  
Eine Schwachstelle in Software, die zu Sicherheitsproblemen führen kann.

### W

**Webhook**  
Ein Mechanismus, der es GitHub ermöglicht, Ereignisse an externe Dienste zu senden, wenn bestimmte Aktionen in einem Repository auftreten.

**Wiki**  
Ein kollaboratives Dokumentationstool, das in GitHub-Repositories verfügbar ist und es ermöglicht, umfangreiche Dokumentation zu erstellen und zu bearbeiten.

**Workflow**  
Eine automatisierte Prozedur in GitHub Actions, die durch bestimmte Ereignisse ausgelöst wird und aus einem oder mehreren Jobs besteht.

**Working Directory**  
Das lokale Verzeichnis auf dem Computer, in dem die Dateien eines Git-Repositories gespeichert sind.

### Y

**YAML**  
Eine menschenlesbare Datenserialiserungssprache, die häufig für Konfigurationsdateien in GitHub verwendet wird, insbesondere für GitHub Actions-Workflows.

## Git-Befehle

Hier ist eine Übersicht der wichtigsten Git-Befehle, die bei der Arbeit mit GitHub verwendet werden:

### Grundlegende Befehle

**git init**  
Initialisiert ein neues Git-Repository im aktuellen Verzeichnis.
```bash
git init
```

**git clone**  
Erstellt eine lokale Kopie eines Remote-Repositories.
```bash
git clone https://github.com/benutzername/repository.git
```

**git add**  
Fügt Dateien zur Staging-Area hinzu, um sie für den nächsten Commit vorzubereiten.
```bash
git add dateiname.txt    # Fügt eine bestimmte Datei hinzu
git add .                # Fügt alle geänderten Dateien hinzu
```

**git commit**  
Erstellt einen neuen Commit mit den Änderungen in der Staging-Area.
```bash
git commit -m "Beschreibung der Änderungen"
```

**git status**  
Zeigt den Status des Arbeitsverzeichnisses und der Staging-Area an.
```bash
git status
```

**git diff**  
Zeigt Unterschiede zwischen Arbeitsverzeichnis, Staging-Area und letztem Commit an.
```bash
git diff                 # Unterschiede zwischen Arbeitsverzeichnis und Staging-Area
git diff --staged        # Unterschiede zwischen Staging-Area und letztem Commit
```

**git log**  
Zeigt die Commit-Historie an.
```bash
git log
git log --oneline        # Kompakte Darstellung
git log --graph          # Grafische Darstellung der Branches
```

### Branch-Befehle

**git branch**  
Listet Branches auf, erstellt neue Branches oder löscht Branches.
```bash
git branch               # Listet alle lokalen Branches auf
git branch neuer-branch  # Erstellt einen neuen Branch
git branch -d branch-name # Löscht einen Branch
```

**git checkout**  
Wechselt zu einem anderen Branch oder Commit.
```bash
git checkout branch-name # Wechselt zu einem Branch
git checkout -b neuer-branch # Erstellt einen neuen Branch und wechselt zu ihm
```

**git switch**  
Ein neuerer Befehl zum Wechseln zwischen Branches.
```bash
git switch branch-name   # Wechselt zu einem Branch
git switch -c neuer-branch # Erstellt einen neuen Branch und wechselt zu ihm
```

**git merge**  
Führt Änderungen aus einem Branch in den aktuellen Branch zusammen.
```bash
git merge branch-name
```

**git rebase**  
Wendet Commits aus einem Branch auf einen anderen an, um eine lineare Historie zu erzeugen.
```bash
git rebase branch-name
```

### Remote-Befehle

**git remote**  
Verwaltet Remote-Repositories.
```bash
git remote -v            # Zeigt alle Remote-Repositories an
git remote add origin https://github.com/benutzername/repository.git # Fügt ein Remote-Repository hinzu
```

**git fetch**  
Lädt Änderungen aus einem Remote-Repository herunter, ohne sie zu integrieren.
```bash
git fetch origin
```

**git pull**  
Lädt Änderungen aus einem Remote-Repository herunter und integriert sie in den aktuellen Branch.
```bash
git pull origin main
```

**git push**  
Überträgt lokale Änderungen an ein Remote-Repository.
```bash
git push origin main
```

### Fortgeschrittene Befehle

**git stash**  
Speichert temporär Änderungen, die noch nicht committet wurden.
```bash
git stash               # Speichert Änderungen
git stash pop           # Wendet gespeicherte Änderungen an und entfernt sie aus dem Stash
git stash list          # Zeigt alle gespeicherten Stashes an
```

**git reset**  
Setzt den aktuellen Branch auf einen bestimmten Zustand zurück.
```bash
git reset --soft HEAD~1  # Setzt den HEAD zurück, behält Änderungen in der Staging-Area
git reset --mixed HEAD~1 # Setzt den HEAD und die Staging-Area zurück, behält Änderungen im Arbeitsverzeichnis
git reset --hard HEAD~1  # Setzt den HEAD, die Staging-Area und das Arbeitsverzeichnis zurück
```

**git revert**  
Erstellt einen neuen Commit, der die Änderungen eines früheren Commits rückgängig macht.
```bash
git revert commit-hash
```

**git cherry-pick**  
Wendet die Änderungen eines bestimmten Commits auf den aktuellen Branch an.
```bash
git cherry-pick commit-hash
```

**git tag**  
Erstellt, listet oder löscht Tags.
```bash
git tag                  # Listet alle Tags auf
git tag v1.0.0           # Erstellt einen leichtgewichtigen Tag
git tag -a v1.0.0 -m "Version 1.0.0" # Erstellt einen annotierten Tag
```

**git blame**  
Zeigt, wer welche Zeilen in einer Datei wann geändert hat.
```bash
git blame dateiname.txt
```

**git bisect**  
Hilft, den Commit zu finden, der einen Fehler eingeführt hat, durch binäre Suche.
```bash
git bisect start
git bisect bad           # Markiert den aktuellen Commit als fehlerhaft
git bisect good commit-hash # Markiert einen bekannten guten Commit
# Git führt dann durch die binäre Suche
git bisect reset         # Beendet die Suche
```
